## Summary

Complete compiler support for `src/Onnxify.Tests/Assets/panlingo-lstm.onnx` so it can generate executable TorchSharp C# and preserve its sequence-processing behavior.

## Current Findings

- The model accepts `int64[-1,-1]` and returns `float32[-1,12]`.
- Its 18 nodes use `Gather`, `LSTM`, `ReduceSum`, and `Identity`; `Gather` and `Identity` were mapped by OXY-036 and `ReduceSum` is now mapped bidirectionally.
- The LSTM node is a generic node with `direction=bidirectional`, `hidden_size=256`, `layout=0`, four populated inputs (`X`, `W`, `R`, `B`), and all three outputs (`Y`, `Y_h`, `Y_c`).
- ONNX-to-generated-TorchSharp execution now matches ONNX Runtime for dynamic input shapes `[1,32]` and `[2,16]`.
- The separate Deep Import → Deep Export path has a Panlingo parity test, but that path is not evidence of compiler LSTM support.
- The compiler's ONNX → TorchSharp LSTM lowering executes and matches ONNX Runtime; reverse operator scanning is supported through the ordinary bidirectional compiler mapping for `torch.nn.functional.lstm`.
- The Panlingo fixture passes the complete ONNX → compiler tree → compiler-emitted ONNX and generated TorchSharp C# path. A separate attempt to export the implementation body of TorchSharp's own `nn.LSTM.forward` is outside this operator-level contract: its nullable tuple state is not an ONNX graph input type. This does not block the canonical compiler LSTM mapping and is not routed through Deep Export.

## Goals

- Add reusable bidirectional mappings for ONNX LSTM while preserving sequence outputs, state outputs, attributes, and optional input semantics.
- Keep the already mapped `Gather`/`Identity` behavior and `ReduceSum` axes/keepdims/no-op semantics covered in both directions.
- Support the model's dynamic batch/sequence dimensions and `int64` token input.

## Tests

- `PanlingoLstmRoundTripTests` exercises ONNX import/export, generated C# compilation/execution, and ONNX Runtime numerical parity.
- `ReduceSumCompilerTests` exercises TorchSharp-to-ONNX and ONNX-to-generated-TorchSharp parity.
- Add focused bidirectional LSTM operator tests and verify the Panlingo fixture through the compiler operator pipeline. The separate Deep Import → Deep Export test is not compiler coverage.

## Acceptance Criteria

- The complete model graph imports/exports, generated C# compiles and runs, and dynamic shapes match ONNX Runtime within the test tolerance.
- ONNX LSTM operator support has paired directional verification for its declared supported scope.
- The canonical TorchSharp functional LSTM operation is recognized by the normal compiler frontend and maps to ONNX `LSTM`; ONNX-imported LSTM generates executable TorchSharp code with matching output.
- The Panlingo fixture roundtrips through the compiler and matches source ONNX Runtime for deterministic token IDs of shapes `[1,32]` and `[2,16]`.
