## Summary

Define the compiler-owned intermediate representation, computation-tree model, normalized attributes, source spans, and diagnostics needed by both directions.

## Depends On

- [OXY-020](OXY-020.md).

## Goals

- Represent tensors, scalar constants, optionals, sequences, tuples, symbolic/fixed dimensions, parameters, buffers, and initializers.
- Represent graph inputs, outputs, intermediate values, module calls, reusable blocks, and operator applications.
- Represent ordered C# syntax semantics: blocks, declarations, assignments, returns, references, literals, arrays, tuples, indexers, and safe static control flow.
- Define normalized operator attributes and operation capability classification: bidirectional, export-only, import-only, unsupported.
- Define diagnostics with stage, severity, source span, and caller/callee context.
- Keep the intermediate representation independent of raw decompiler AST and TorchSharp runtime objects.

## Tests

- Intermediate-representation round-trip serialization or structural equality tests for representative nodes.
- Diagnostics tests cover unsupported, ambiguous, and lossy mappings.
- Symbolic dimensions and tensor metadata remain lossless in the intermediate representation.

## Verification

- Representative intermediate-representation fixtures are constructed, compared, and round-tripped by automated tests.
- Tests assert diagnostic stage/severity/span and capability classification for unsupported and lossy operations.

## Acceptance Criteria

- Both ONNX and C# frontends can target the same compiler-owned intermediate-representation types.
- No direction-specific intermediate-representation duplicate is introduced in a consumer project.
