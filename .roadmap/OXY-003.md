## Summary

Add the "IR to OnnxGraph" half of deep export for the minimal IR subset created in `OXY-002`.

This task proves the scanner/printer architecture end to end without attempting broad syntax or operator migration.

## Depends On

- `OXY-001`: metadata and diagnostics foundation
- `OXY-002`: IR and scanner skeleton

## Enables

- `OXY-004`: basic data-flow migration
- `OXY-008`: public extension hardening

## Goals

- Add printer abstractions and ordered printer registry.
- Add `DeepExportValue` categories.
- Print the minimal IR subset into an `OnnxGraph`.
- Preserve graph naming where current tests depend on names.
- Delegate graph fragments to existing helpers whenever possible.
- Keep fallback to the old exporter for unsupported IR.

## Non-Goals

- Do not migrate complex control flow.
- Do not migrate all Torch operations.
- Do not remove old `ExportValue` or old dictionaries unless they are unused by the minimal path.
- Do not finalize public extension APIs.

## Core Types

### DeepExportValue

Introduce typed value categories:

- `GraphEdgeValue`
- `TensorInitializerValue`
- `ScalarValue`
- `ArrayValue`
- `TupleValue`
- `ModuleValue`
- `MethodValue`
- `ShapeDimensionValue`
- `SymbolicTensorMemberValue`
- `NullValue`
- `RuntimeObjectValue` as an isolated escape hatch

Avoid new raw `object` flows except inside `RuntimeObjectValue`.

### DeepExportPrintContext

Expose internally:

- `OnnxGraph Graph`
- `DeepExportModuleMetadata Metadata`
- `DeepExportShapeTypeResolver ShapeTypes`
- local value scope
- diagnostics
- `NextName(prefix)` naming helper
- helper methods to require graph edge, scalar, array, tuple, or module values

### Printer Registry

`DeepExportPrinterRegistry` must provide:

- deterministic ordered dispatch
- specific IR printers before generic printers
- structured no-match diagnostics
- optional fallback marker for old path

## Minimal Print Coverage

Print the minimal IR from `OXY-002`:

- block
- parameter reference
- local variable declaration
- local reference
- return
- tensor method invocation for one safe operation, preferably `relu`

The tensor operation printer should call an existing graph helper instead of hand-building a one-off node when possible.

## End-To-End Path

Add an internal path:

```text
decompile forward
scan minimal IR
print minimal IR
connect declared outputs
return OnnxModel
```

This path may be gated internally until enough tests pass. The public API can still fall back to the old monolith for unsupported syntax.

## Module Exporter Bridge

Create an internal bridge that lets a known TorchSharp module exporter participate in printer output:

- accept module value
- accept graph edge input value
- call existing `TorchModuleExtensions.Export(...)`
- return `GraphEdgeValue`

Only cover the minimal case here. Broad recursive module export belongs in `OXY-006`.

## Tests

Add focused tests for:

- printer registry ordering
- minimal IR prints an ONNX graph
- minimal scanned-and-printed module emits expected node type
- ONNX Runtime session can be created for the minimal emitted graph
- TorchSharp eager output matches ONNX Runtime output for the minimal module
- unsupported IR node falls back or fails with structured diagnostics, depending on the chosen internal gate

## Acceptance Criteria

- At least one tiny deep export fixture uses the new scanner/printer path end to end.
- Existing public deep export tests still pass.
- Minimal printer layer emits graph nodes without calling the old statement/expression interpreter.
- `DeepExportValue` is used by the new printer path.
- Unsupported non-minimal cases still use the old behavior or fail with a clear internal diagnostic in test-only paths.

## Risks

- A parallel minimal path can diverge from existing graph naming. Keep names stable where practical.
- It is tempting to migrate many operators once the path works. Stop after the minimal proof and leave broad migration for `OXY-007`.
