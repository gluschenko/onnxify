## Summary

Establish the compiler-owned operator mapping contract and prove it with one bidirectional ReLU mapping. Migrate the remaining operator families in follow-up roadmap tasks.

## Depends On

- [OXY-021](OXY-021.md).
- [OXY-022](OXY-022.md).
- [OXY-023](OXY-023.md).

## Goals

- Define one mapping contract for parse/import and print/export behavior.
- Classify every mapping as bidirectional, export-only, import-only, or unsupported.
- Implement ReLU as the first bidirectional mapping, including ONNX import/emission and C# TorchSharp import/generation.
- Keep operation-specific lowering out of `TorchModuleExportExtensions.cs` and ModelGenerator registries as migration proceeds.
- Require every new operator to have verification from `ONNX -> TorchSharp` and `TorchSharp -> ONNX`.

## Follow-up Operator Families

- [OXY-029](OXY-029.md): arithmetic and broadcasting.
- [OXY-030](OXY-030.md): matrix multiplication.
- [OXY-031](OXY-031.md): shape operations and factories.
- [OXY-032](OXY-032.md): activations beyond ReLU.
- [OXY-033](OXY-033.md): selection, reductions, and casts.

## Tests

All shared operator tests belong in `src/Onnxify.Compiler.Tests/Onnxify.Compiler.Tests.csproj` and must link to the exact upstream source tests.

- ReLU has structural graph and generated-source assertions in both directions.
- ONNX Runtime session creation is tested where the emitted graph is executable.
- Deterministic ReLU fixtures compare TorchSharp eager output with ONNX Runtime output in both directions.
- Unsupported ReLU overloads produce explicit diagnostics instead of silently generating invalid code.

## Verification

- For ReLU, paired tests start from an ONNX fixture and from a TorchSharp fixture.
- Both paths assert the shared mapping identity/capability, emitted graph or generated code, and runtime/numerical parity.
- CI/test review fails the phase if an operator has only one directional test without an explicit tested one-way classification.

## Acceptance Criteria

- A compiler-owned mapping registry is used by the ONNX frontend/backend and C# TorchSharp frontend/backend.
- ReLU is implemented through one shared bidirectional mapping with paired directional verification.
- Unknown ONNX operators retain generic passthrough behavior and an explicit unsupported warning.
- Adding an operator requires paired directional verification or an explicit tested one-way classification.
