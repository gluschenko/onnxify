# OXY-028: OnnxGraph Stale Value And Dead Node Cleanup

## Summary

Add a graph-level `Clean()` operation to `OnnxGraph` that removes stale, unreachable, and otherwise unused graph data before an ONNX model is serialized or executed.

The motivating log shows ONNX Runtime removing many unused initializers created by generated models, including values such as `ones_5`, `full_like_19_value`, `zeros_like_value`, and related factory constants. The cleanup should make this liveness pass explicit in Onnxify instead of relying on ONNX Runtime to repair the generated graph at session creation time.

## Depends On

- Existing `OnnxGraph` node/edge mutation and serialization APIs.
- Existing generated-model smoke and ONNX Runtime compatibility tests in `src/Onnxify.Tests`.

## Goals

- Add the method with the fixed name `OnnxGraph.Clean(...)`; do not introduce alternative public names such as `RemoveUnusedValues(...)` or `CleanStaleValues(...)`.
- Make `Clean(...)` accept a byte-backed flags enum with this public shape:

  ```csharp
  [Flags]
  public enum OnnxGraphCleanupFlags : byte
  {
      Nodes = 1 << 0,
      Values = 1 << 1,
      Initializers = 1 << 2,
      Inputs = 1 << 3,
      Outputs = 1 << 4,
      Subgraphs = 1 << 5,
      Annotations = 1 << 6,
      ValueInfo = Values,
      Constants = Initializers,
      NestedGraphs = Subgraphs,
      QuantizationAnnotations = Annotations,
      All = 0x7F
  }

  public OnnxGraphCleanupReport Clean(
      OnnxGraphCleanupFlags flags = OnnxGraphCleanupFlags.All
  );
  ```

  The intended flag values are bit shifts to the left. Writing `1 >> 1`, `1 >> 2`, and `1 >> 3` would evaluate to zero and would not produce distinct flags.

  Flag responsibilities:

  - `Nodes`: remove dead/orphan nodes;
  - `Values`: remove stale intermediate `ValueInfo` entries and unused node edge references;
  - `Initializers`: remove unused dense and sparse constants;
  - `Inputs`: remove inputs proven not to be part of the retained graph contract, only when explicitly requested;
  - `Outputs`: remove orphan outputs only when explicitly requested, never as an implicit side effect of ordinary cleanup;
  - `Subgraphs`: recursively clean nested graph attributes with isolated name scopes;
  - `Annotations`: remove stale quantization/value annotations and other graph annotations whose referenced values no longer exist.

  `Inputs` and `Outputs` are intentionally separate from ordinary liveness cleanup because they are part of the graph's public contract. `Metadata`/documentation strings, model-level functions, and training info are not included in this `OnnxGraph` enum: they are not graph liveness data and should be handled by a separate model-level policy if needed.
- Compute liveness from graph outputs backwards through node inputs and producer relationships.
- Remove unused initializers, including scalar/factory constants and sparse initializer data where supported.
- Remove stale intermediate `ValueInfo` entries and orphan node outputs that are not needed by live graph results.
- Remove dead nodes when none of their outputs can contribute to a graph output, while preserving nodes with side-effect or control-flow semantics if the model format requires them.
- Preserve graph inputs, graph outputs, live node order, live producer-consumer references, metadata required for serialization, and externally referenced values.
- Recurse into nested graph attributes/subgraphs where cleanup is safe, without treating a subgraph's local names as parent-graph values.
- Remove stale quantization/value annotations only when their referenced graph values are removed.
- Make cleanup deterministic and idempotent.
- Return a useful cleanup report or counts so callers and tests can see what was removed.
- Integrate cleanup at the appropriate model-generation/serialization boundary without forcing callers to depend on ONNX Runtime.

## Non-Goals

- Do not use cleanup to hide invalid shape metadata or runtime shape mismatches.
- Do not rewrite tensor values, change operator semantics, fold constants, or perform general graph optimization in this task.
- Do not remove graph inputs or outputs merely because they are currently unused; preserve the declared public graph contract unless an explicit future option says otherwise.
- Do not remove an initializer that is also a required graph input or is referenced by a nested graph.

## Observed Runtime Symptoms

The supplied ONNX Runtime log reports repeated warnings from `Graph::CleanUnusedInitializersAndNodeArgs` for unused initializers such as `ones_*`, `zeros_like_*`, and `full_like_*_value`. It also reports separate shape metadata warnings, including a declared dimension `0` versus an actual dimension `1`. The stale-value cleanup must address the former and leave the latter visible for a separate shape-validation decision.

## Proposed Algorithm

1. Establish live roots from declared graph outputs and any values required by graph-level control-flow/state semantics.
2. Walk backwards from live values through producer nodes, marking every required node input, initializer, graph input, `ValueInfo`, and nested graph reference.
3. Remove dead nodes and their now-unreferenced outputs in a safe dependency order.
4. Remove unreferenced initializers and stale intermediate `ValueInfo` records while retaining public inputs/outputs and required metadata.
5. Rebuild or validate indexes/references, preserve deterministic ordering, and verify that serialization produces a self-consistent graph.
6. Apply the same analysis to nested subgraphs with isolated scopes when the ONNX attribute semantics permit it.

The implementation should use the existing `OnnxGraph` mutation/reference-replacement primitives instead of introducing a second graph model or ad-hoc name scanning.

## Implementation Steps

1. Inventory how `OnnxGraph` stores nodes, initializers, value info, inputs, outputs, sparse tensors, and nested graph attributes.
2. Define liveness roots, scope rules, preservation rules, `OnnxGraphCleanupFlags`, and a cleanup report type.
3. Implement `OnnxGraph.Clean(...)` and deterministic liveness traversal in `src/Onnxify/OnnxGraph.cs` or a clearly owned helper.
4. Add safe nested-subgraph handling and ensure all graph indexes/reference lists remain consistent after removal.
5. Decide and document where generated graphs invoke cleanup by default, and provide an opt-out only if compatibility requires it.
6. Add a regression fixture reproducing unused `ones`, `zeros_like`, and `full_like` initializer patterns.
7. Validate serialized cleaned graphs through ONNX Runtime and confirm cleanup is idempotent.

## Tests

- An unused initializer is removed while a live initializer remains.
- Unused scalar/factory constants, sparse initializer data, and stale `ValueInfo` entries are cleaned where supported.
- A dead node is removed without removing a live producer or changing graph outputs.
- Graph inputs and outputs are preserved exactly.
- Shared values with multiple consumers remain until all consumers are dead.
- Nested subgraphs are cleaned with correct local scope handling.
- Cleanup is deterministic and a second invocation removes nothing further.
- `Clean(Nodes)`, `Clean(Values)`, `Clean(Initializers)`, `Clean(Subgraphs)`, and `Clean(Annotations)` affect only their selected cleanup categories. `Clean(Inputs)` and `Clean(Outputs)` require explicit opt-in. `Clean(All)` enables the complete pass.
- Cleaned graphs serialize and create an ONNX Runtime session.
- The generated-model regression no longer causes ONNX Runtime unused-initializer warnings attributable to stale graph data.
- Shape mismatch diagnostics from the supplied log remain observable and are not silently “fixed” by stale-value cleanup.

## Verification

- Compare node, initializer, value-info, input, and output counts before and after cleanup using the returned report.
- Verify each individual flag and `All` combination, including that flags do not accidentally evaluate to zero.
- Assert that every remaining node input resolves to a declared input, initializer, or live producer output.
- Assert that every remaining initializer/value-info entry is referenced or intentionally preserved by the graph contract.
- Serialize the cleaned graph, create an ONNX Runtime session, and compare deterministic outputs with the uncleaned graph.
- Invoke cleanup twice and assert structural equality after the first and second invocation.

## Acceptance Criteria

- `OnnxGraph` exposes the documented method `Clean(...)` with byte-backed flags, deterministic behavior, and an inspectable result.
- Generated graphs can be cleaned before runtime/serialization without changing executable outputs.
- The supplied class of unused initializer warnings is eliminated at the source for the regression fixture.
- Cleanup handles values, constants, node outputs, metadata, and nested scopes according to explicit liveness rules.
- Shape metadata mismatches remain separate diagnostics and are covered by a separate decision/test rather than being hidden.

## Risks

- ONNX graph inputs and initializers can share names; liveness must distinguish declaration roles without deleting a required input.
- Optional inputs, variadic outputs, control-flow subgraphs, and local nested scopes can make simple name-based reachability incorrect.
- Removing dead nodes may expose malformed graphs that ONNX Runtime previously tolerated; serialization and runtime validation must remain part of the test gate.
- Automatically cleaning every graph could surprise callers that inspect intermediate artifacts, so the default integration point and opt-out behavior must be explicit.
