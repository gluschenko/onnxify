## Summary

Extend the shared compiler pipeline across method and module boundaries while preserving scopes, metadata, and generated module structure.

## Depends On

- [OXY-023](OXY-023.md).
- [OXY-024](OXY-024.md).

## Goals

- Support local and generated helper methods, helper parameter binding, returns, tuples, and arrays.
- Support known module `forward` calls, sequential traversal, and recursive user modules.
- Preserve child metadata contexts and include caller/callee names in diagnostics.
- Support arrays, tuples, deconstruction, shape/dtype reads, static branches, validation/no-grad scopes, and safe static iteration.
- Keep dynamic or unsafe control flow explicitly unsupported.

## Tests

- Helper projection, scalar arguments, tuple returns, deconstruction, split/slice helpers, known modules, sequential chains, and recursive child modules.
- Static shape/control-flow tests and diagnostics for dynamic control flow.
- ONNX Runtime and TorchSharp parity for deterministic helper/module fixtures.

## Verification

- Helper/module fixtures assert caller-to-callee binding, child scopes, return ordering, and recursive metadata context.
- Static-control-flow fixtures assert the selected branch/iteration and dynamic-control-flow fixtures assert the intended diagnostic.
- Deterministic fixtures are executed through both TorchSharp and ONNX Runtime where supported.

## Acceptance Criteria

- Helper and module paths no longer require the old monolithic interpreter for migrated constructs.
- Recursive module and static control-flow semantics are represented in the shared tree.
