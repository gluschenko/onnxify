## Summary

Implement the C# TorchSharp side of the compiler: adapt decompiled/source computation into the shared tree and generate readable executable TorchSharp module code as a `string`.

## Depends On

- [OXY-020](OXY-020.md).
- [OXY-021](OXY-021.md).

## Goals

- Define compiler-owned scanner contracts and deterministic most-specific-first dispatch.
- Ingest `forward(...)` bodies, module metadata, parameters, buffers, helper calls, and supported static control flow.
- Provide a thin TorchSharp adapter for runtime model/source access without moving compiler logic into `Onnxify.TorchSharp`.
- Generate readable TorchSharp module code from the tree.
- Preserve compatibility with current computational-scenario reconstruction.

## Tests

- A minimal TorchSharp module scans into the compiler intermediate representation.
- The backend returns compilable C# source as a `string`.
- Generated code reconstructs an executable module for a minimal fixture.
- Unsupported syntax produces diagnostics or uses an explicitly temporary compatibility fallback.

## Verification

- A minimal TorchSharp fixture is scanned into the compiler tree and the generated C# `string` is compiled.
- The generated module executes on deterministic input and its output is compared with the source module.
- The test records whether unsupported syntax used a fallback or produced a diagnostic.

## Acceptance Criteria

- `CreateTreeFromTorchSharp(...)` and `GenerateCSharp(tree)` are usable through compiler-backed consumer APIs.
- Generated C# is TorchSharp computational code, not merely an ONNX Runtime wrapper.
