## Summary

Make existing public APIs delegate to `Onnxify.Compiler` and expose a narrow, stable extension surface for compiler consumers.

## Depends On

- [OXY-020](OXY-020.md).
- [OXY-023](OXY-023.md).
- [OXY-024](OXY-024.md).

## Goals

- Keep existing ModelGenerator and TorchSharp public overloads source-compatible.
- Add compiler-backed options for diagnostics, debug IR, runtime metadata reflection, and extension collections where appropriate.
- Support narrow custom metadata providers, module exporters, scanners, printers, and method lowerings.
- Define deterministic extension priority and strict/permissive failure behavior.
- Deprecate or remove old direction-specific registries only after equivalent compiler mappings exist.

## Tests

- Existing public APIs delegate to compiler services.
- External-style consumer compiles against the extension surface.
- Custom providers, exporters, scanners, printers, priority overrides, ambiguity, and strict/permissive exceptions are covered.

## Verification

- A consumer-style test calls existing public overloads and observes compiler-backed behavior.
- Extension tests prove deterministic priority, ambiguity diagnostics, and strict/permissive exception behavior.
- A compatibility audit identifies each remaining old registry/path and its retirement condition.

## Acceptance Criteria

- No new feature work is directed to the old monolithic path.
- Compatibility façades and extension points are documented and tested.
