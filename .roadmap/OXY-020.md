## Summary

Create `src/Onnxify.Compiler/` and establish the acyclic dependency boundary required by OXY-019. The compiler project owns compiler contracts and orchestration; `Onnxify.ModelGenerator` and `Onnxify.TorchSharp` become consumers with thin adapters.

## Depends On

- OXY-019 architecture and package ownership decision.
- Existing `Onnxify`, `Onnxify.ModelGenerator`, and `Onnxify.TorchSharp` projects.

## Goals

- Add `Onnxify.Compiler` to `src/Onnxify.slnx`.
- Reference only core `Onnxify` from the compiler project.
- Add compiler project references from `Onnxify.ModelGenerator` and `Onnxify.TorchSharp`.
- Define source/sink and compiler-session contracts without referencing either consumer project.
- Define the initial public orchestration shape for creating trees and generating ONNX/C# output.

## Non-Goals

- Do not migrate operator implementations yet.
- Do not introduce TorchSharp or ModelGenerator references into `Onnxify.Compiler`.

## Tests

- Solution and affected projects restore/build with the new references.
- A dependency check proves the compiler has no reverse reference to either consumer.
- Minimal contract smoke tests compile from both consumer projects.

## Acceptance Criteria

- The project exists, is in the solution, and has the intended dependency direction.
- Compiler-owned contracts can represent ONNX and TorchSharp computation sources without a cyclic dependency.
