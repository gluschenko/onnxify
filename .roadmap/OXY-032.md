## Summary

Extend the shared activation mapping family after the foundational bidirectional ReLU mapping in OXY-024.

## Depends On

- [OXY-024](OXY-024.md).

## Goals

- Audit activation spellings, attributes, defaults, and overloads against ONNXScript and ONNX Runtime source tests.
- Add complete family mappings to `Onnxify.Compiler`, including normalization of supported attributes.
- Diagnose unsupported activation overloads explicitly.

## Implemented Scope

- Added shared bidirectional mappings for Celu, Elu, Gelu, HardSigmoid, HardSwish, LeakyRelu, Mish, PRelu, Relu, Selu, Sigmoid, Softplus, Softsign, Swish, Tanh, and ThresholdedRelu.
- Preserved attribute defaults and validated supported ONNX/TorchSharp forms. ThresholdedRelu accepts only the zero replacement value in TorchSharp calls.
- Swish is exported as an ONNX `Sigmoid` + `Mul` graph because the selected ONNX Runtime CPU provider does not implement the Swish operator kernel.
- Composite TorchSharp activations without a distinct ONNX identity (for example LogSigmoid and ReLU6) are not declared as direct operator mappings in this task.

## Tests

- Add paired directional fixtures for every declared activation and relevant attribute/default case.
- Assert shared mapping identity, graph/source structure, ONNX Runtime session creation, and deterministic numerical parity.
- Link exact upstream test functions/groups in test comments.

## Acceptance Criteria

- Every declared activation has paired verification or an explicitly tested one-way classification.
