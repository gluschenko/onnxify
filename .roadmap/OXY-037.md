## Summary

Add general compiler support needed to import, generate TorchSharp for, and round-trip `src/Onnxify.Tests/Assets/bvlcalexnet-12-qdq.onnx`.

## Current Findings

- The model has 63 nodes, including 15 `QuantizeLinear`, 28 `DequantizeLinear`, 2 `LRN`, and 3 `MaxPool` nodes.
- The input and output are float32 tensors with fixed shapes `[1,3,224,224]` and `[1,1000]`.
- Q/DQ nodes use three inputs (`data`, `scale`, `zero_point`) without operator attributes in this fixture. Conv, MatMul, Reshape, Add, Relu, and Softmax already have compiler mappings.
- Compiler mappings for import/export and TorchSharp emission have been started for Q/DQ, LRN, and MaxPool. Q/DQ emission currently models the fixture's uint8 affine quantization with rounded/clamped float code tensors between Q and DQ.
- The fixture imports successfully after the mappings were added. Its opset-12 `Reshape` exposed a separate schema-version export failure; the `Reshape` mapping now preserves the legacy node schema during ONNX export, matching the existing legacy `Cast` strategy.
- Generated-source compilation, model execution, and ONNX Runtime parity have not yet been confirmed. Q/DQ mappings are currently import-only and do not yet provide TorchSharp-to-ONNX scanning.

## Goals

- Implement reusable mappings for Q/DQ quantization semantics, `LRN`, and the model's `MaxPool` cases.
- Preserve per-tensor/per-channel scale and zero-point behavior supported by this asset.
- Verify the generated module against source ONNX Runtime results.

## Tests

- Do not add a model-specific test before the complete model path is supported.
- Once supported, add an integration test in `Onnxify.Compiler.Tests` with generated-source compilation and runtime parity.

## Acceptance Criteria

- ONNX import/export preserve the model graph semantics without unsupported generic nodes.
- Generated C# compiles and matches the source model on deterministic image-shaped input.
