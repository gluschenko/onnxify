## Summary

Add reusable structured runtime control flow to the compiler representation and connect the C# TorchSharp and ONNX frontends/backends. OXY-039 reverse LSTM export depends on this work.

## Scope

- Runtime `if` and structured `for`/`while` loops with captures and loop-carried values.
- `break` and `continue` within supported loop bodies.
- ONNX `If` and `Loop` graph attributes, including branch outputs, captures, loop-carried values, and scan outputs.
- Preserve existing compile-time `if` and `foreach` behavior. Arbitrary `goto` and irreducible control flow are out of scope.

## Current Findings

- The compiler tree has explicit runtime `if`, `for`/`while`, `break`, and `continue` syntax, and the C# frontend retains dynamic conditional expressions and null patterns.
- The C# backend emits these constructs. A deterministic fixture containing nested conditions, `break`, `continue`, and loop-carried locals compiles and executes through TorchSharp.
- ONNX `If` and `Loop` nodes, graph-valued attributes, nested branches, captures, and carried values survive generic-node import/export. Tests execute nested `If` and condition-terminated `Loop` models in ONNX Runtime.
- The ONNX backend now lowers runtime C# `if` to `If`, and `for`/`while` to `Loop` with captures and carried tensor/scalar values. The lowering was exercised through ONNX Runtime for both `if` branches, zero/multiple-iteration loops, a carried-value `for`, direct `break`, and `continue` through a `for` incrementor.
- Imported ONNX `If`/`Loop` nodes continue to roundtrip as structured nodes, including nested captures and carried values; ONNX Runtime tests now also cover Loop scan outputs with zero and multiple iterations.
- Remaining C# lowering limits include early returns nested inside runtime branches or loops, static foreach over non-literal collections, and arbitrary helper calls. Nested conditional `break`/`continue` now flow through per-iteration active/break flags; both ONNX Runtime and generated TorchSharp parity are exercised.
- OXY-039 still depends on lowering the actual TorchSharp LSTM module's runtime control flow and its mapped operator calls through the ordinary compiler pipeline. Do not count Deep Export/module-exporter parity as compiler reverse-path coverage, and do not generate NativeMethods as a substitute.

## Acceptance Criteria

- C# frontend retains supported runtime branches and loops in compiler-owned IR; generated C# preserves their execution behavior.
- ONNX `If` and `Loop` import/export roundtrips preserve graph structure, value types, shapes, captures, and outputs.
- Tests cover both runtime `if` branches, captures, loop-carried values, condition termination, zero/multiple iterations, scan outputs including zero trips, and direct `break`/`continue` semantics including `for` incrementors.
- Imported ONNX control-flow and C#-lowered `if`/loops execute in ONNX Runtime and generated TorchSharp parity tests.
- Remaining acceptance: early-return behavior and the Panlingo LSTM compiler reverse path through standard compiler mappings.
