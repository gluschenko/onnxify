## Summary

Implement the ONNX side of the compiler: import an ONNX model/file into the shared computation tree and emit an `OnnxGraph` from that tree.

## Depends On

- [OXY-020](OXY-020.md).
- [OXY-021](OXY-021.md).

## Goals

- Read graph nodes, inputs, outputs, initializers, value metadata, attributes, and supported subgraphs.
- Preserve names, tensor types, dimensions, constants, and module/state information where available.
- Emit valid `OnnxGraph` structures from compiler IR.
- Support file, stream, and in-memory model entry points through existing core model I/O conventions.
- Produce clear diagnostics for unsupported or ambiguous ONNX patterns.

## Tests

- Minimal ONNX graph imports into IR and emits equivalent graph structure.
- Initializers, symbolic dimensions, attributes, and graph names are preserved.
- ONNX Runtime can create a session for emitted graphs where kernels exist.
- Invalid and unsupported graphs produce stage-aware diagnostics.

## Acceptance Criteria

- `CreateTreeFromOnnx(...)` works for a model/file input.
- `GenerateOnnx(tree)` emits a valid graph without consumer-package compiler logic.
