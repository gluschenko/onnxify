## Summary

Implement the ONNX side of the compiler: import an ONNX model/file into the shared computation tree and emit an `OnnxModel` or `OnnxGraph` from that tree.

## Depends On

- [OXY-020](OXY-020.md).
- [OXY-021](OXY-021.md).

## Goals

- Add `OnnxCompilerSession` and the `Compiler` model/graph import and export facade.
- Read model envelopes, graph nodes, inputs, outputs, initializers, sparse initializers, value metadata, attributes, quantization annotations, and nested subgraphs.
- Preserve names, tensor types, fixed/symbolic/unknown dimensions, constants, ordered wires, metadata, opset imports, and nested outer-scope captures.
- Emit valid `OnnxModel` and `OnnxGraph` structures from compiler IR, including generic unknown operators.
- Support file, stream, in-memory, and asynchronous model entry points through existing core model I/O conventions.
- Produce clear stage-aware diagnostics for unsupported, ambiguous, lossy, missing-reference, and invalid ONNX patterns.

## Tests

- Minimal ONNX graph imports into IR and emits equivalent model and graph structures.
- Dense and sparse initializers, symbolic/unknown dimensions, scalar/tensor/array/TypeProto/graph attributes, and graph names are preserved.
- Model envelope, metadata, opset imports, quantization annotations, nested `If`/`Loop`/`Scan` graphs, and captures round-trip through the compiler IR.
- ONNX Runtime can create a session for emitted `Identity`/`Add` graphs.
- File, stream, and asynchronous entry points plus independent structural-equality checks are covered.
- Invalid and unsupported graphs produce stage-aware diagnostics.

## Verification

- Compiler tests pass on `net8.0` and `net10.0`; the compiler project also builds for `netstandard2.0`.
- Independent minimal ONNX fixtures are imported and emitted again; node names, attributes, types, dimensions, initializers, sparse data, nested graphs, captures, and envelope fields are asserted.
- The emitted model is loaded by ONNX Runtime for runtime-backed `Identity` coverage.

## Acceptance Criteria

- `CreateTreeFromOnnx(...)` works for model, file, stream, and asynchronous inputs.
- `GenerateOnnx(tree)` emits a valid model and `GenerateOnnxGraph(tree)` emits a valid graph without consumer-package compiler logic.
- The ONNX model/graph boundary is validated by serializing and reloading the emitted model.
- OXY-022 implementation is complete; OXY-023—OXY-027 remain unchanged.
