## Summary

Port the Hugging Face JSON artifact source-generation idea from Cognetium into `Onnxify.ModelGenerator`.

The source feature lives at:

```text
D:\GitHub\cognetium\src\GPTRunner.HuggingFaceArtifacts.SourceGenerator
```

The goal is to let projects generate typed C# wrappers for non-ONNX Hugging Face repository artifacts such as `config.json`, `generation_config.json`, `tokenizer_config.json`, `special_tokens_map.json`, `preprocessor_config.json`, and similar model metadata files.

This should complement ONNX model wrapper generation. It should not turn every random `.json` file in a project into a generated class unless the project opts into that behavior.

## Source Findings

The Cognetium generator is a `netstandard2.0` Roslyn incremental source generator implemented mainly in `HuggingFaceInferenceArtifactGenerator.cs`.

Important behavior to preserve or adapt:

- It scans `AdditionalTextsProvider` for `.json` files.
- It supports per-file opt-out through `build_metadata.AdditionalFiles.GenerateHuggingFaceInferenceArtifact`.
- It resolves generated namespace from per-file metadata, then `RootNamespace`, then `AssemblyName`, then `Generated`.
- It resolves generated class name from per-file metadata or a safe identifier derived from the JSON filename.
- It resolves generated accessibility from per-file metadata and normalizes to `public` or `internal`.
- It reports diagnostics for invalid JSON and unsupported non-object roots.
- It emits one generated source file per JSON artifact with a stable hint name based on the generated class and file path.
- It infers C# property models from JSON object shape.
- It emits `[JsonPropertyName(...)]` for original JSON names.
- It emits `[JsonExtensionData]` so unknown or future fields are preserved.
- It emits `Deserialize(string, JsonSerializerOptions?)`, `Load(string, JsonSerializerOptions?)`, and `Serialize(JsonSerializerOptions?)`.
- It emits nested classes for nested JSON objects.
- It merges object arrays into one nested item type based on all observed properties.
- It falls back to `JsonElement` when a type is empty, mixed, null-only, or otherwise not safely inferable.
- It has a root-dictionary mode for large or scalar-keyed objects, but the current implementation builds a wrapper that only exposes extension data and does not yet surface the inferred dictionary type directly.
- It uses a simple safe-identifier helper that PascalCases names and removes punctuation.

Relevant differences in `Onnxify.ModelGenerator`:

- `Onnxify.ModelGenerator` already consumes `AdditionalFiles` for `.onnx` files and reads `build_metadata.additionalfiles.OnnxifyModelClassName`, `OnnxifyModelNamespace`, and `OnnxifyModelImportType`.
- `Onnxify.ModelGenerator.targets` already defines an `OnnxModel` item and maps it into `AdditionalFiles`.
- New JSON artifact support should fit this existing package and MSBuild style instead of creating a separate generator package.
- Tests should live in `src/Onnxify.Tests`, near existing `OnnxModelGeneratorTests`.

## Enables

- Typed access to Hugging Face model metadata without hand-written POCOs.
- Generated wrappers that can inspect tokenizer/config/generation metadata alongside ONNX model wrappers.
- Future chat-template support that can consume `tokenizer_config.json`, `special_tokens_map.json`, and related artifacts.
- Better generated projects for downloaded Hugging Face repositories.
- Safer handling of fast-moving Hugging Face metadata through `[JsonExtensionData]`.

## Goals

- Add Hugging Face artifact generation to `Onnxify.ModelGenerator`.
- Introduce an explicit MSBuild item such as `HuggingFaceArtifact` rather than scanning every `.json` by default.
- Support common Hugging Face JSON artifacts:
  - `config.json`
  - `generation_config.json`
  - `tokenizer_config.json`
  - `special_tokens_map.json`
  - `preprocessor_config.json`
  - `processor_config.json`
  - `tokenizer.json` when generation is explicitly requested
- Generate typed partial classes with JSON property attributes, extension data, load/deserialize/serialize helpers, and nested types.
- Preserve original JSON property names and provide safe, unique C# property names.
- Keep generated code deterministic across runs.
- Report actionable diagnostics for invalid JSON, unsupported roots, duplicate generated artifact type names, and unsupported metadata values.
- Update package docs and release notes if this becomes package-visible behavior.

## Non-Goals

- Do not parse binary artifacts, safetensors, protobuf, sentencepiece, vocab text, or merges files in this task.
- Do not generate tokenizer logic from `tokenizer.json`; only generate typed metadata access when explicitly requested.
- Do not make all project `.json` files opt-in automatically.
- Do not replace `Onnxify.HuggingFace` download behavior.
- Do not infer a perfect schema for every possible Hugging Face metadata variant.
- Do not generate mutable runtime configuration logic; generated artifact classes should be plain data wrappers.

## MSBuild API Shape

Add a dedicated item in `Onnxify.ModelGenerator.props` / `.targets`:

```xml
<ItemGroup>
  <HuggingFaceArtifact Include="config.json"
                       OnnxifyArtifactClassName="ModelConfig"
                       OnnxifyArtifactNamespace="Demo.Models.Artifacts"
                       OnnxifyArtifactAccessibility="public" />
</ItemGroup>
```

Suggested item metadata:

- `OnnxifyArtifactClassName`: optional generated class name override.
- `OnnxifyArtifactNamespace`: optional generated namespace override.
- `OnnxifyArtifactAccessibility`: `public` or `internal`, default `internal`.
- `OnnxifyArtifactKind`: optional friendly kind such as `Config`, `TokenizerConfig`, `GenerationConfig`, `SpecialTokensMap`, `PreprocessorConfig`, or `GenericJson`.
- `OnnxifyArtifactGenerate`: optional boolean, default `true` for `HuggingFaceArtifact` items.

Suggested properties:

- `EnableDefaultHuggingFaceArtifactItems`: default `false`.
- `OnnxifyDefaultHuggingFaceArtifactGlobs`: optional semicolon-separated default includes for known HF artifact filenames.

The `.targets` file should expose relevant item metadata to the generator through `CompilerVisibleItemMetadata` and map `@(HuggingFaceArtifact)` into `AdditionalFiles` without interfering with `@(OnnxModel)`.

Avoid reusing Cognetium metadata names such as `GeneratedClassName` directly unless backward compatibility with copied project files is explicitly desired.

## Generated API Shape

Generated classes should be small data models:

```csharp
public sealed partial class ModelConfig
{
    [JsonPropertyName("model_type")]
    public string? ModelType { get; init; }

    [JsonExtensionData]
    public Dictionary<string, JsonElement>? ExtensionData { get; init; }

    public static ModelConfig? Deserialize(string json, JsonSerializerOptions? options = null);

    public static ModelConfig Load(string path, JsonSerializerOptions? options = null);

    public string Serialize(JsonSerializerOptions? options = null);
}
```

Additional API details:

- Use `global::` qualification where it improves generated-code robustness.
- Emit `#nullable enable`.
- Keep classes `sealed partial` so consumers can extend them.
- Prefer `IReadOnlyDictionary<string, JsonElement>?` only if `System.Text.Json` extension data supports the chosen shape cleanly; otherwise keep `Dictionary<string, JsonElement>?`.
- Consider async load helpers only after the synchronous shape is stable.
- Keep generated artifact types independent from ONNX Runtime and TorchSharp dependencies.

## Type Inference Rules

Start from the Cognetium inference behavior, then make the rules explicit:

- JSON object: nested generated class unless dictionary fallback is clearly better.
- JSON array of strings: `string[]?`.
- JSON array of integers fitting `int`: `int[]?`.
- JSON array of numbers: `double[]?`.
- JSON array of booleans: `bool[]?`.
- JSON array of objects: nested item class generated from the union of observed properties.
- Empty or mixed arrays: `JsonElement[]?` or `JsonElement?` based on the chosen API.
- JSON string: `string?`.
- JSON integer fitting `int`: `int?`; evaluate whether `long?` is safer for HF metadata.
- JSON number: `double?`.
- JSON boolean: `bool?`.
- Null-only or unknown fields: `JsonElement?`.
- Large scalar-keyed objects: dictionary-like representation or extension-data wrapper, with the decision recorded before implementation.

Identifier generation must handle:

- punctuation and hyphens
- leading digits
- duplicate property names after sanitization
- reserved member names such as `Load`, `Serialize`, `Deserialize`, `ExtensionData`, `Equals`, `GetHashCode`, and `ToString`
- nested type names colliding with property names

## Design Questions

- Should artifact generation be implemented inside `OnnxModelGenerator` or split into a separate internal generator/service class that the package registers from the same assembly?
- Should common Hugging Face artifact filenames get conventional class names such as `ModelConfig`, `GenerationConfig`, `TokenizerConfig`, and `SpecialTokensMap`?
- Should default artifact item inclusion remain off, or should generated projects from `Onnxify.ProjectGenerator` opt into known HF filenames?
- Should numeric inference use `int`, `long`, or a conservative `JsonElement` for large metadata values?
- Should root dictionaries expose a typed dictionary property instead of only `[JsonExtensionData]`?
- Should generated classes include `FromFile` / `FromStream` names to align with existing Onnxify file API naming?
- Should this task update `Onnxify.HuggingFace` or `Onnxify.ProjectGenerator` docs to show downloaded artifacts being generated?

## Acceptance Criteria

- `Onnxify.ModelGenerator` can generate typed C# classes for explicitly included Hugging Face JSON artifacts.
- The generated code compiles in the existing source-generator test harness.
- Artifact generation does not change existing `.onnx` wrapper output.
- MSBuild item metadata is documented and tested.
- Invalid or unsupported artifacts produce clear diagnostics.
- Generated classes preserve unknown future fields through extension data.
- The implementation is deterministic across repeated runs.
- Package docs and release notes describe the new artifact generation workflow.

## Risks

- Inferring schemas from a single JSON sample can overfit one model repository. Preserve extension data and use conservative fallback types.
- Scanning all `.json` files by default could surprise users. Keep generation explicit unless a generated project intentionally opts in.
- Adding another input pipeline to `OnnxModelGenerator` can make the main generator too large. Prefer a focused service class.
- Dictionary fallback behavior in the Cognetium version is useful but incomplete. Decide whether to expose a typed dictionary property before porting it verbatim.
- Hugging Face artifacts evolve quickly; avoid generating brittle classes that reject unknown fields.
