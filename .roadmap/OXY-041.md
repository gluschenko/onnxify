## Summary

Support the dynamic input shapes and operator forms required to compile `src/Onnxify.Tests/Assets/mobilenetv2-12.onnx` through generated TorchSharp and ONNX Runtime.

## Current Findings

- The model input is float32 `[-1,3,224,224]`; output is float32 `[-1,1000]`.
- Clip bounds are float32 tensors of shape `[1]`, not rank-0 scalar tensors; the previous validator incorrectly rejected these valid one-element broadcasts.
- The opset-12 graph contains a tensor-valued `Constant`, legacy `Unsqueeze` with an `axes` attribute, and `Shape`. Typed current-schema `Unsqueeze` and `Shape` wrappers caused import/export schema-version issues.
- Generic tensor-`Constant` and legacy-`Unsqueeze` mappings are implemented. `Shape` and `Unsqueeze` emission preserve the original ONNX schema for the source opset.
- Permanent end-to-end validation passes import/export, generated C# compilation, ONNX Runtime session creation, and batch-1 numerical parity. The fixture's dynamic batch metadata and runtime output shape `[1,1000]` are asserted.

## Goals

- Generalize `Clip` input handling for the supported ONNX forms and connect static values through the compiler representation.
- Support the model's dynamic batch dimension and its shape-manipulation subgraph without model-specific branches.

## Tests

- Do not add a model-specific test while import reports errors or generated C# cannot execute.
- Once supported, test a deterministic input with batch size one through generated TorchSharp and both source and emitted ONNX Runtime.

## Acceptance Criteria

- Import, ONNX emission, generated C# compilation, and runtime execution succeed for a representative dynamic batch.
- Generated and emitted-model outputs match the source model within a documented tolerance.
