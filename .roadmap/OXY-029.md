# OXY-029: Compiler Operator Mappings: Pointwise Operations And Broadcasting

## Summary

Add shared compiler mappings for deterministic elementwise operations and their supported TorchSharp spellings, including multidirectional broadcasting. The audited set covers arithmetic, numeric unary functions, comparisons, logical operators, pointwise selection, casts, and activations. Shape-changing, matrix, reduction, and nondeterministic operators remain in their own family tasks.

## Depends On

- [OXY-024](OXY-024.md).
- [OXY-034](OXY-034.md).

## Goals

- Select the supported pointwise set from the intersection of ONNXScript TorchLib converter cases and ONNX Runtime runtime tests before declaring completion.
- Implement mappings only in `Onnxify.Compiler` and preserve explicit constraints for supported overloads and broadcasting.
- Support tensor and representable scalar operands through compiler constants/ONNX initializers.
- ONNX `Mod` with default/floor remainder semantics is imported; TorchSharp `remainder` exports through `Div`/`Floor`/`Mul`/`Sub`, while ONNX `fmod=1` is rejected because its mixed-sign semantics differ.
- Keep unsupported signatures, dtypes, and known-incompatible broadcasting diagnostic; preserve generic unknown ONNX operators.
- Retain activation mappings already introduced by OXY-024/OXY-032 without duplicating their implementation.

## Audited Mapping Inventory

The currently implemented pointwise subset has the following ONNX identities. All entries are `Bidirectional` unless identified as one-way below.

- Arithmetic and numeric binary functions: `Add`, `Sub`, `Mul`, `Div`, `Pow`, `Max`, `Min`, and `Mod`.
- Numeric unary functions: `Abs`, `Neg`, `Exp`, `Log`, `Sqrt`, `Floor`, `Ceil`, `Sin`, `Cos`, `Tan`, `Asin`, `Acos`, `Atan`, `Sinh`, `Cosh`, `Asinh`, `Acosh`, `Atanh`, `Erf`, `Reciprocal`, `Round`, and `Sign`.
- Comparisons and logical operations: `Equal`, `Greater`, `GreaterOrEqual`, `Less`, `LessOrEqual`, `And`, `Or`, `Xor`, and `Not`.
- Pointwise selection and type conversion: `Where`, `Cast`, `IsNaN`, and `IsInf`.
- Activations retained from OXY-024/OXY-032: `Celu`, `Elu`, `Gelu`, `HardSigmoid`, `HardSwish`, `LeakyRelu`, `Mish`, `PRelu`, `Relu`, `Selu`, `Sigmoid`, `Softplus`, `Softsign`, `Swish`, `Tanh`, and `ThresholdedRelu`.
- `Trunc` is `ExportOnly`; it lowers to ONNX `Mod` and `Sub`. `Mod` imports only `fmod` unset/zero; `fmod=1` is rejected because its sign behavior differs from TorchSharp remainder.
- Export-only composite mappings lower through typed standard ONNX nodes: `Exp2` (`Pow`), `Log1p` (`Add`, `Log`), `Log10`/`Log2` (`Log`, `Div`), `LogAddExp`/`LogAddExp2`, `Lerp`, `AddCdiv`, `AddCmul`, `Deg2Rad`, `Rad2Deg`, and `Rsqrt`. They use compiler-owned identities in `com.onnxify.compiler`; their generated ONNX subgraphs are runtime-tested, and import back to TorchSharp C# is explicitly rejected by their `ExportOnly` capability.

The paired runtime suite currently verifies Float32 for the ordinary arithmetic, unary, comparison, logical, activation, and `Where` cases; Boolean tensors for logical operators; Float64 `Add`; Int32 `Mod`; and Float32-to-Int64 `Cast`. Arithmetic scalar initializers are verified for Add/Sub/Mul/Div/Pow, including reversed scalar/tensor order for Sub and Div. Broadcasting is verified for tensor ranks one through three and statically incompatible dimensions. This is a tested representative dtype set, not a complete per-operator dtype matrix.

The audit includes these additional upstream cases from `third_party/onnxscript/tests/function_libs/torch_lib/ops_test_data.py`: `exp2`, `log1p`, `log10`, `log2`, `lerp`, `logaddexp`, `logaddexp2`, `addcdiv`, `addcmul`, `deg2rad`, `rad2deg`, and `rsqrt`. Their converter definitions are in `third_party/onnxscript/onnxscript/function_libs/torch_lib/ops/core.py` (functions `aten_exp2`, `aten_log1p`, `aten_log10`, `aten_log2`, `aten_lerp`, `aten_logaddexp`, `aten_logaddexp2`, `aten_addcdiv`, `aten_addcmul`, `aten_deg2rad`, `aten_rad2deg`, and `aten_rsqrt`). Runtime coverage uses ONNX Runtime CPU `math/element_wise_ops_test.cc` cases for the constituent `Pow`, `Log`, `Exp`, `Add`, `Sub`, `Mul`, `Div`, `Sqrt`, `Reciprocal`, `Less`, and `Where` operators.

Explicit exclusions and boundaries:

- `atan2` (`aten_atan2` in ONNXScript `ops/core.py`) is excluded from exact decomposition: the TorchLib implementation applies quadrant corrections, and signed-zero cases require preserving `atan2(+0, -x) = +pi`; the available pointwise operators do not currently provide the needed guarantee.
- `signbit` (`aten_signbit`) is excluded because `Less(x, 0)` does not distinguish negative zero, as the upstream implementation notes.
- `equal` is an all-elements reduction returning a scalar Boolean, not a pointwise comparison; it belongs to OXY-033. Pointwise `ne` remains an audit candidate.
- `fmod` is not equated with remainder: ONNX `Mod(fmod=1)` has different import behavior and is currently rejected by the `Mod` mapping. TorchSharp `remainder` retains its separately tested floor-remainder lowering.
- The new composite scan accepts scalar operands only when they are compile-time constants; dynamic scalar parameters are rejected with a source-span diagnostic. Its current scalar initializer implementation supports Float32 and Float64 tensor inputs only.
- `clamp`, `clamp_min`, and `clamp_max` remain import-only or unsupported for TorchSharp scanning; the full overload and optional-bound audit remains open.

These additions close several known candidate gaps but do not yet close the complete upstream inventory or the dtype matrix. In particular, `isfinite`, `isclose`, `heaviside`, `logit`, `xlogy`, `frac`, `floor_divide`, and pointwise clamp variants still require a documented exactness decision and compiler/runtime coverage before the task can be marked complete.

## Tests

- Add paired ONNX-to-TorchSharp and TorchSharp-to-ONNX tests for each declared operator and supported broadcast case, including generated TorchSharp compilation/execution.
- Assert mapping identity/capability, graph or generated source structure, ONNX Runtime session creation, and deterministic numerical parity.
- Link each test to exact ONNXScript and ONNX Runtime source cases. Composite export-only mappings must assert the standard emitted node sequence, ORT execution, eager TorchSharp parity, and a diagnostic when reverse generation is requested.
- Current ONNXScript source: `third_party/onnxscript/tests/function_libs/torch_lib/ops_test_data.py`, cases named in the family tests and inventory above. Runtime sources: `third_party/onnxruntime/onnxruntime/test/providers/cpu/math/element_wise_ops_test.cc`, `third_party/onnxruntime/onnxruntime/test/providers/cpu/tensor/where_op_test.cc`, `third_party/onnxruntime/onnxruntime/test/providers/cpu/tensor/isinf_test.cc`, `third_party/onnxruntime/onnxruntime/test/providers/cpu/tensor/cast_op_test.cc`, and `third_party/onnxruntime/onnxruntime/test/providers/cpu/activation/activation_op_test.cc`.

## Acceptance Criteria

- Every operator in the declared family has paired directional coverage or an explicitly tested one-way capability.
- Broadcast/type limitations and unsupported overload diagnostics are recorded alongside the tests.
- OXY-033 is limited to reductions and selection that is not pointwise; OXY-027 depends on this task and OXY-030—OXY-033.
