## Summary

Complete compiler support for the repository's Panlingo transformer fixture so it can be imported from ONNX, generated as TorchSharp C#, executed, and round-tripped through ONNX Runtime. The same model exists in `src/Onnxify.Tests/Assets` and `src/Onnxify.ConsoleTest/Assets`.

## Findings Before Implementation

- The graph has 309 ONNX nodes, with 78 currently unsupported compiler steps.
- Unsupported operator families are `Gather` (27), `LayerNormalization` (17), `Softmax` (8), `Dropout` (24), `Shape`, and `Identity`.
- The input is `int64[-1,256]`; the output is `float32[0,256,13594]`.
- ONNX import and ONNX emission currently succeed with generic passthrough warnings, but TorchSharp C# generation fails because unsupported operations have no import mapping.

## Goals

- Add reusable bidirectional operator support and preserve dynamic sequence dimensions and integer token inputs.
- Validate the complete model through generated TorchSharp execution and ONNX Runtime parity.

## Tests

- Added `PanlingoTransformerRoundTripTests` in `Onnxify.Compiler.Tests`, covering supported operator counts, generated C# compilation/execution, emitted ONNX session creation, and source/generated/emitted numerical parity.
- Added generated-code handling for unused auxiliary outputs from multi-output nodes; ONNX emission retains the complete node output list.
- Operator-source provenance comments link to ONNXScript converter/test data, ONNX Runtime Gather/Softmax/Dropout/Shape/Identity tests, and the generated ONNX LayerNormalization schema documentation.

## Acceptance Criteria

- The model imports without unsupported-operation diagnostics and emits ONNX without generic passthrough warnings.
- Generated C# compiles, executes for a deterministic `[1,256]` token input, and matches the source model within an explicitly measured tolerance.
